# Fixtures

Example Evaluation/Test Engine output (module 2), conforming exactly to
the **"2 → 3" contract** in `docs/architecture.md`. Used by:

- `src/scoring` and `src/report`'s own tests (`node --test`)
- manual runs of the Report Engine CLI before modules 1/2 exist:
  `node src/report/cli.js fixtures/evaluation-output.simple.v1.json`

| File | complexity_class | Purpose |
|---|---|---|
| `evaluation-output.simple.v1.json` | `simple` | First evaluation of a small, single-task skill; several findings of mixed severity. |
| `evaluation-output.simple.v2.json` | `simple` | A revised version of the same skill (same `skill_path`) with most issues fixed — pairs with v1 to demo the version comparison. |
| `evaluation-output.multi-step.v1.json` | `multi_step_process` | A multi-step automated skill, exercising the process-only metrics (`process_logic`, `dependency_clarity`, `workflow_robustness`) and a `CRITICAL` finding. |

These are hand-written stand-ins for module 2's real output — not
generated by it — since this module was built in parallel against the
documented contract, not module 2's actual code.

## Skill fixtures (input for the Analyzer, module 1)

| Directory | Expected class | Why it exists |
|---|---|---|
| `simple-skill/` | `simple` | Minimal single-task skill, no steps or tools. |
| `multi-step-skill/` | `multi_step_process` | Numbered workflow list with conditions, a retry, a feedback loop, and `references/`/`scripts/`/`assets/`. |
| `heading-steps-skill/` | `multi_step_process` | Workflow expressed as `## Step N:` **headings** — the form real skills actually use most, and the one the original heuristics missed entirely. |
| `catalog-skill/` | `simple` | Several scripts and plenty of conditional prose, but no sequence — a catalogue of independent recipes. This is the shape (`pdf`, `docx`, `xlsx`, `pptx`) that the original classifier wrongly called a multi-step process. |

The last two were added after running the analyzer against a corpus of 40
real skills. The first two alone were shaped exactly like the heuristics
expected, which is why every test passed while real skills were being
misclassified — new fixtures should model how skills are really written,
not how the code wishes they were.
